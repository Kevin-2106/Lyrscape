# 文字 PV renderer

2026-10-13 重做，同日新增三种；10-14 新增晴空终端与晴空终端 II；10-17 新增晴空终端 III、一起出发与游戏开发部，并统一了检查器页签。十一种可独立选择、启停和配置的可信内置 renderer。最初三种按 `qa/pv-references/` 中三支 DECO*27 PV 逐帧研究的字体、配色与特效重新实现，共用一个 canvas 舞台。默认仍是普通文字；AMLL adapter 与这些 renderer 独立。

## 使用

打开「插件 › 渲染器」，在左侧列表选择对应风格。右侧检查器不再分「选项 / 文字」两层，而是把渲染器自己的配置项（按 `group` 分类）和共享文字设置合并成一排页签，顺序为 选项 · 构图 · 动效 · 特效 · 字体 · 颜色 · 显示，只显示有内容的页签：

- 渲染器在 manifest 中用 `theme` 声明使用哪些共享设置（`font` / `color` / `nextLine`，省略为全部）。普通文字与 Aurora 显示 字体 / 颜色 / 显示；PV 风格声明 `theme: []`，共享设置只剩「显示」（字号、背景不透明度、显示译文），不再显示改了也不生效的颜色 / 渐变 / 字体；Apple Music 风格声明 `['font']`。
- 同名页签合并：PV 的「颜色」「字体」页签放的是渲染器自己的颜色和字体选项，有共享设置时用「X · 渲染器」小标题分开。
- 每页底部「恢复本页默认」只重置这一页的配置项与共享设置；没有改动时按钮不可用。

PV 风格自带字体与配色（按歌词语言在简体 / 繁体 / 日文字体间切换，见 [字体与歌词语言](fonts.md)）。所有 PV 风格新增了共享可调项（Apple Music 风格没有「动效速度」）：

| 页签 | 配置项 |
| --- | --- |
| 构图 | 构图（自动 / 按段落识别副歌 / 全部大字 / 全部字幕）、整体大小 |
| 动效 | 动效开关、动效强度（0–2，进场位移、过冲、抖动、故障与粒子飞散的幅度，1 为参考 PV 力度）、动效速度（0.5–2，进场与退场动画的快慢；字词出现的时刻始终跟随歌词）、跟随节拍 |
| 字体 | 字体：风格默认、黑体、宋体 / 明朝、圆体、粗圆体、楷体 / 手写、波普、粗黑装饰体、等宽、像素。替换的是中日文字形，HUD / 衬线译文等拉丁专用字体不变 |
| 颜色 | 每种风格的主要颜色（HEX 颜色选择器），见下 |
| 特效 | 每种风格的装饰开关 |

构图「自动」时，同一文档中重复出现的行（副歌）和不超过 7 个字的短句用大字构图，其余用字幕构图；也可固定为全部大字或全部字幕。

「自动 · 按段落识别副歌」（可选）按段落而不是按行判断：找出至少连续 2 行、在歌曲别处再次出现的段落（逐行按编辑距离模糊匹配，相似度 ≥ 60%，所以第二遍副歌改了一个词仍算同一段；段中允许夹一行不同的行），每次出现都整段标为副歌，再把夹在两行副歌之间、只出现一次的行也并入。副歌段内不超过 22 个字的行用大字，其余全部用字幕；单独重复的一行主歌和主歌里的短句不再升为大字。整首歌找不到重复段落时退回「自动」规则。只看歌词文本，不分析音频；超过 400 行的部分不参与检测。其他配置：整体大小、动效开关、跟随节拍强度（见 [节拍检测](beat-detection.md)），以及每种风格自己的倾斜 / 柔光 / 星星 / 平移、光晕颜色 / 花瓣、文字颜色（浅色泡沫或原 PV 深墨色）/ 故障强度 / 巨型汉字 / 微缩字；晴空终端的故障强度 / 青柠光环图标 / 标题与时间码。

旧的 `pv-impact / pv-card / pv-cut` 选择会迁移到 `pv-pop / pv-letter / pv-elegy`，旧配置字段不再适用，恢复为默认值。

## Apple Music 风格（AMLL）

按 [AMLL](https://github.com/amll-dev/applemusic-like-lyrics)（AGPL-3.0）提交 `86200de` 的歌词播放器**行为与参数**独立实现，未复制其代码：

- 左对齐粗体列表，当前行顶部位于舞台高度的 30%（可调），其余行按距离变暗（35%）、缩小到 97%、模糊 `min(5, 1 + 距离)` px（按字号缩放），焦点切换时 0.4 s 过渡。
- 逐词时间：已唱部分全白、未唱 42%，扫光前沿为半个字高的柔边；唱到的词在 max(1 s, 词长) 内上浮 0.05 em。≥ 1 s 的短词（≤ 7 字）逐字放大、外推并发白光，参数同 AMLL 的 emphasize 公式。逐行时间时当前行整行点亮。
- 滚动弹簧：质量 0.9，刚度 170–220（随与上一行的间隔变化），阻尼 √k × 2.2；首行用慢速参数 90 / 15；向下每行延迟 50 ms（递减 1.05 倍）。用弹簧的**解析阶跃响应**叠加最近几次焦点变化求位置，所以仍是时间轴的纯函数：暂停静止、seek 直接得到同一画面；残余位移小于 0.2 px 时归零，静止时不会亚像素抖动。
- 背景人声以 0.7 倍、40% 显示在所属行下方并占位；两句之间空出 ≥ 4 s 时显示三个呼吸圆点，按间隔进度逐个点亮。
- 未实现：对唱右对齐（当前歌词模型没有对唱字段）、拖动 / 滚轮浏览。
- 配置：整体大小、显示行数（2–6）、当前行位置、远处模糊、间奏圆点、动效。

Apple Music 风格与合成谱为深色背景设计，在浅色桌面上靠柔和暗阴影保持可读；需要更强对比时调高「背景不透明度」。

## 时间规则

- 每帧都是 timeline 绝对位置的纯函数：暂停停在当前帧，seek 直接得到对应画面，跨窗口同步不累积动画。随机感（星星、花瓣、故障块、构图偏移）全部按行 ID 与文本做种子，同一时刻总是同一画面。
- 退场边界取当前行结束时间与下一条前景行开始时间的较早值，不从字数推算演唱速度。上一行可与下一行的进场短暂重叠，最多同时绘制 3 行。
- 只有真实细分的逐字 / 逐词数据才驱动「唱到才出现 / 唱到再亮」；一个覆盖整句的片段按逐行处理。没有逐词数据时字幕一次打出、词组按固定节奏解码，不伪造演唱进度。
- 纯文本（无时间）以字幕构图显示全部行，用 mount 的本地时钟进场一次。
- 格式有问题的歌词：自身结束时间不晚于开始时间的行（如网易云把「作词 / 作曲」标为 0:00 → 0:00）不显示；与后一条前景行开始时间相同的行被后一条取代（与普通文字的 `activeLine` 一致）。此前这类行在 PV 中永不退场，会和正常歌词同时显示。
- 双语 LRC：紧跟在一行后面、时间戳（含多时间戳行的整组）完全相同、且不带逐字标记的行，解析为前一行的译文；再有一行则为音译。不相邻的同时间戳行、带逐字时间的行和空行仍是独立的歌词行。
- 节拍效果只在实时 PCM 驱动时叠加，不进入时间轴纯函数；暂停时没有音频，因此暂停画面仍然静止。
- 系统减少动态效果或关闭动效时，直接绘制静止的最终构图；退场变为直接消失。

## 实现

- `src/plugins/pv/stage.ts`：共享 canvas 舞台。调度可见行、按 DPR 设置画布、缓存布局、为无障碍与测试写入隐藏文本 `.pv-text` 与 `data-pv-style / data-pv-line / data-pv-lines`（本帧绘制的全部行 ID）`/ data-pv-mode / data-pv-beat`（锁定的 BPM）。舞台高度只由字号、缩放与译文开关决定，overlay 窗口高度不会随动画抖动。
- `src/plugins/pv/{pop,letter,elegy,vamp,synth,halo,halo3,azure,gamedev}.ts`（halo.ts 导出晴空终端与晴空终端 II 两个变体，halo3 复用其窗口卡片与背景）：每种风格的 `layout`（每行一次，预渲染样式化字形精灵）与 `draw`（每帧只做变换、裁带与合成）；可选 `backdrop` 每帧在歌词下方画一次（合成谱 / 游戏开发部的 HUD），可选 `overlay` 在歌词上方画一次（游戏开发部的 CRT 扫描线），`audio: true` 读取实时频谱。
- `src/plugins/pv/pixel.ts`：像素字形。把一个字栅格化到 32 × 32 格（24 格 / em），可加粗、圆角化（模糊 + 阈值），绘制柔影、细边、硬投影，或只画部分格子（抖动溶解、点阵回声）。
- 动效强度与速度由舞台统一处理：`env.amp` 交给各风格缩放幅度；速度按比例缩放动画用的行内时间并缩短退场，字词出现时刻不变，仍是时间轴的纯函数。
- `src/plugins/pv/amll.ts`：scene 模式，`scene()` 拿到整份歌词与布局缓存自行排版整列，其余（画布、DPR、出血边距、字体、无障碍文本）仍由舞台负责。
- `src/plugins/pv/core.ts`：缓动、种子随机、grapheme / 词切分、日语文节近似断行（不让助词或送假名起行）、行边界与副歌判定。
- `src/plugins/pv/paint.ts`：离屏精灵、带状绘制与形状（扇贝、星星、爱心）。
- `src/plugins/pv/fonts.ts`：随应用打包的 OFL 字体（@fontsource 与霞鹜文楷，按 unicode-range 子集按需加载，不访问网络）；字体加载完成后自动重建布局。`vite.config.ts` 去掉了 .woff 后备，只打包 woff2（`dist` 约 60 MB）。
- `src/plugins/typeface.ts`：歌词语言判断与「角色 × 语言」字体表；风格通过 `line.face(role)` / `line.tface(role)` 取字体，见 [字体与歌词语言](fonts.md)。
- 每行最多绘制 160 个 grapheme（超出以「…」截断），限制精灵数量；隐藏文本保留全文。

所有特效都在单个每帧清空的 canvas 内完成，不使用 DOM 上的 CSS filter、遮罩或变换字层，避免透明 overlay 的残影问题（见 [Overlay 验证](overlay-validation.md)）。canvas 内部的 `filter: blur()`（情书的聚焦效果）不产生 DOM 合成层。

## 复验

```powershell
node scripts/smoke-pv.mjs
```

原生 overlay 使用独立 WebView2 数据目录与 CDP 9228，不能指向用户正常实例：

```powershell
$env:LYRSCAPE_CDP = 'http://127.0.0.1:9228'
node scripts/smoke-pv.mjs
node scripts/prepare-overlay-fixture.mjs --pv=pop
./scripts/capture-overlay-screen.ps1 -AppProcessId <隔离实例PID> -OutputDirectory qa/pv-screen-pop -FrameCount 90 -IntervalMs 50
./scripts/analyze-overlay-frames.ps1 -Directory qa/pv-screen-pop -FailOnContamination
```
